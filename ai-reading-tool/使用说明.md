# 读数工具 · 脱离助手独立运行说明

这个文件夹是自包含的：**拷到电脑任何位置（或别的机器）都能用**，不依赖任何对话助手。

## 一、里面有什么

| 文件 | 作用 |
|---|---|
| `read_one.py` | 读数主程序（检测 + 姿态推理 + 几何协议 + 拒读 + 可视化） |
| `runs/det_full/weights/best.pt` | 检测模型权重（数字 10~50 mm，1280 训练，mAP50 0.979） |
| `runs/pose_full/weights/best.pt` | 姿态模型权重（刻度线 + 叉丝，1280 训练，mAP50 0.990） |
| `读一张.bat` | 单图读数：把图片拖到它上面，或双击后输入路径 |
| `批量读数.bat` | 整个文件夹批量读数，结果存 `result.csv`，图存 `vis\` |

## 二、第一次用之前（只需一次）

需要 Python 3.10+ 和依赖库。装好 Python 后执行：

```bash
pip install ultralytics
```

（会自动带上 torch、opencv、numpy）

两个 `.bat` 会按顺序自动探测能用的 Python：`python` → `py -3` →
`%USERPROFILE%\miniconda3\envs\aii\python.exe` → `%USERPROFILE%\anaconda3\envs\aii\python.exe`，
取第一个**已装 ultralytics** 的。一个都找不到时，bat 会提示你先 `pip install ultralytics`。
不依赖任何写死的本机路径。

## 三、日常使用

**方式 1（最简单）**：把图片（或装图片的文件夹）拖到对应的 `.bat` 上。

**方式 2**：双击 `.bat`，然后**把文件夹直接拖进那个黑窗口**（路径会自动填进去），回车。

**方式 3（命令行）**：

```bash
cd 读数工具
python read_one.py --image "D:\图片\IMG_0001.jpg"        # 单张
python read_one.py --image "D:\图片" --save-csv r.csv    # 整目录批量 + 明细表
```

批量结果：`读数工具\result.csv`（每张一行：读数、截距、相对残差、状态），可视化在 `读数工具\vis\`。
180 张大约 1 分钟（CPU），跑的时候窗口会逐张打印 `进度 3/180`。

**路径怎么填都行**：带不带引号、结尾带不带 `\`、中文和空格路径都已经处理过。
如果提示 `Folder not found`，就是路径确实不存在（复制路径时注意别少了盘符）。

输出解读：
- `读数 : 37.4 mm` —— 最终结果，按 0.1 mm 报告（与人工估读对齐）
- `残差 : 最大 0.053 mm / 跨度 10 mm = 0.53% → 通过` —— 几何自检，**相对残差超过 1.5% 会拒读**而不是硬报
- `vis\图片名.png` —— 可视化图（锚点、刻度线、叉丝、读数条），**读完会自动用系统看图程序打开**
  单张模式读完直接弹图；批量模式跑完弹 `vis\` 目录。不想弹就加 `--no-show`。

## 四、参数速查

| 参数 | 默认 | 说明 |
|---|---|---|
| `--k` | -0.02388 | 全局斜率 mm/px，全量标注标定，别动 |
| `--rel-resid` | 0.015 | 相对残差上限（残差 / 锚点跨度），拒读门槛，可按需收紧/放宽 |
| `--anchor` | tick | 锚点取对应刻度线；`box` 为讲义原写法（误差更大） |
| `--no-show` | 关 | 只打印路径，不自动打开可视化图 |
| `--no-vis` | 关 | 干脆不画图（批量追速度时用） |
| `--det` / `--pose` | runs\... | 换权重时用 |

## 五、这版模型的实测成绩（36 张验证集）

- 读数 **36 张、拒读 0 张**
- 误差中位 0.050 mm，p95 0.140 mm，最大 0.150 mm，≤0.1 mm 占 78%
- 无系统偏差（+0.038 mm，扣掉偏置后误差反而变大 → 随机抖动，不加补偿）

## 六、批量跑完看哪里

- **`result.csv`**：Excel 直接打开。列分别是 `image, read_mm, b_mm, rel_resid_pct, status`；
  通过的行有读数，拒读的行读数空着、`status` 写原因。**每次批量会覆盖这个文件**，要留档就先改名。
- **`vis\图片名.png`**：可视化。顶部写读数，红圈是锚点（带 `(conf 0.5x)` 的是低置信刻度线），
  蓝线是叉丝，灰短线是每 5 mm 的标尺。**跑完会自动打开**：单张弹这一张，批量弹整个 `vis` 文件夹。
- 别把 `vis\` 里的 png 混进待读目录——它们是带标注框的渲染图，模型照样会去读，结果没有意义。

## 七、以前批量点不动的原因（已修）

`.bat` 在 Windows 命令行里有个老坑：路径结尾若是反斜杠，写成 `"C:\图片\"` 时
`\"` 会被 cmd 当成「转义引号」，把后面的 `--save-csv` 一起吞进路径里。
表现就是窗口一闪、或者报 `unrecognized arguments` / `路径不存在`。
现在两个 bat 都做了去掉首尾引号 + 去尾部反斜杠 + 转绝对路径三步，
带不带引号、带不带尾斜杠、中文与空格路径都测过，可以正常跑。

## 八、拒读了怎么办

先看输出里那句 `相对残差 ... 超阈值`：

- **锚点行里带 `(conf 0.5x)` 的**：那条刻度线模型自己也不确定，已用橙色圈标出、**不参与残差判定**。
  若仍被拒读，说明两条可信刻度线彼此都对不上 → 图确实有问题（糊、反光、刻度被挡）。
- **相对残差 1%~1.5%**：多半只是这张图拍得比平均稍近/稍远（比例尺差 2% 左右），读数照样可信，输出里会正常通过。
- **想放宽**：`--rel-resid 0.02`（默认 0.015）。不建议随手放大——拒读是保护，不是故障。
- **想更严**：`--rel-resid 0.01`（模型自身相对残差 p95 在 0.83% 附近）。

> 为什么不用「残差 ≤ 0.10 mm」：绝对残差随锚点跨度线性放大——跨度 20 mm 的图天然是 10 mm 的 2 倍，
> 同一个成像比例误差会被判成两种结论。实测 130 张 10 mm 跨度图绝对残差 p95 = 0.096 mm，
> 50 张 20 mm 跨度图是 0.322 mm，而相对残差都落在 1% 附近。所以判据用相对量。

## 九、报错了怎么办

| 报错 | 原因 | 现状 |
|---|---|---|
| `OSError: [Errno 22] Invalid argument`（写 `vis\xxx.png`） | 那张 png 正被看图软件 / 预览窗占用，写不进去 | 已修：改 `open(wb)` 写入，被占用就另存 `xxx_2.png`，读数照常输出 |
| `unrecognized arguments: ...` / 窗口一闪而过 | 路径结尾带 `\`，`\"` 被 cmd 当转义引号 | 已修：两个 bat 都做了引号与尾斜杠处理 |
| `Folder not found` | 路径确实不存在 | 检查盘符；拖拽文件夹进黑窗口最稳 |
| `可视化 : 跳过（写入失败…）` | 同上，连 `_2`/`_3` 都写不进（目录只读等） | 图没了但读数正确，换个可写目录即可 |

画图只是附加功能：**任何可视化相关的失败都不会影响读数结果**，屏幕上照样打印锚点、截距、残差、读数。
